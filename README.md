# GMO×国会議員 関係DB

GMOグループと国会議員の関係（ドメイン/サーバー/SSL情報・パーティー券購入・贈答・面談履歴）を記録・可視化するツールです。

- 公開サイト（GitHub Pages）: https://andcokey.github.io/kokkaigiin-kankei-db/
- データ本体: Notion（4データベース: 議員マスタ（全体）712件／関係マスタ（重点対象）41件／接触履歴／データ品質メモ）
- 構成: GitHub Pages（フロント）→ GAS（プロキシ）→ Notion（データ本体）
- フロントは `index.html` をシェルとして「全体サマリ」「個別ページ」「一括追加」をタブで切り替える構成（実体は `summary.html` / `detail.html` / `bulk.html` をiframeで表示）

このリポジトリにはコードのみを置き、実データ・トークンはコミットしません。

## セットアップ手順

### 1. Notion Integrationを作成し、4つのデータベースに接続する

1. https://www.notion.so/profile/integrations で新規Integrationを作成（名前は任意、例:「GMO国会議員関係DB」）
2. 作成したIntegrationのアクセストークンをコピー（後でGASに貼る）
3. Notion側で以下の4データベースそれぞれの「•••」→「接続を追加」から、作成したIntegrationを接続する
   - 議員マスタ（全体）
   - 関係マスタ（重点対象）
   - 接触履歴（面談・贈答・セミナー献金）
   - データ品質メモ

### 2. GASをデプロイする

1. https://script.google.com で新規Apps Scriptプロジェクトを作成
2. `gas/Code.gs` の内容を貼り付ける
3. 「プロジェクトの設定」→「スクリプト プロパティ」に以下を追加
   - `NOTION_TOKEN` … 手順1でコピーしたトークン
   - `SHARED_TOKEN` … フロントと共有する合言葉（好きな文字列。第三者に知られないもの）
4. 「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」→アクセスできるユーザー「全員」でデプロイし、発行されたURLをコピー

### 3. フロントに接続情報を入力する

公開サイトを開くと、初回アクセス時にGASのURLと合言葉の入力を求められます（この端末のブラウザに保存されます）。設定を変更したい場合は各ページ右上の「GAS接続設定を変更」から再入力できます。

## ディレクトリ構成

```
index.html       … シェル（タブバー＋iframe。公開URLはここを開く）
summary.html     … 全体サマリの実体（議員数・パーティー券購入額・ドメイン/サーバー/SSLシェア）
detail.html      … 個別議員ページの実体。現職国会議員712名全員のページがある。?id=<legislator_id>（関係マスタ登録者、例: L001）または?id=<議員マスタ全体のページID>のどちらでも指定可能。未指定時は検索付き選択リストを表示
bulk.html        … CSVによる一括登録・一括追加の実体
gas-client.js     … フロント共通のGAS呼び出しクライアント
gas/Code.gs       … GASプロキシ（Notion API呼び出し・書き込み）
```

summary.html / detail.html は単体でも開けますが（`detail.html?id=L001` を直接開くなど）、通常は `index.html` を開き、タブ間の遷移は `postMessage` で親（シェル）とやり取りしています。

## データモデル

- **議員マスタ（全体）**: 現職国会議員712名。氏名・議院・政党・選挙区・ドメイン/サーバー/SSL情報・現職役職・顔写真URL・ドメイン有効期限。個別ページは712名全員に存在する。
  - **現職役職**は関係マスタ未登録者向けに追加したフィールド。内閣（首相官邸公式サイト）・衆参議長・主要政党代表/幹事長など、公開情報から手動で収集した約22名分のみ入っている（大半の議員は空欄＝「特別な役職なし」を意味する）。今後の内閣改造・党役員人事等で更新が必要。
  - **顔写真URL**（2026-08-14追加）は自民党公式サイト（jimin.jp）の画像を直接参照するURL。現時点では自民党所属議員のみ収集済み（他党は未収集）。他党分を追加する場合も同じ列に外部URLを入力すればdetail.htmlに反映される。
  - **ドメイン有効期限**（2026-08-14追加）はDate型。bulk.htmlの「CSVでドメイン有効期限を一括更新」から登録・更新できる（下記参照）。detail.htmlのドメイン欄に表示され、期限切れ・残り30日以内は色付きで警告表示される。
- **関係マスタ（重点対象）**: 弊社が実際に関係を持つ41名。legislator_id・現職役職・派閥備考・社内担当・送付先情報。「議員マスタ（全体）」への一対一リレーションあり（引退・落選した2名は未リンク）。
- **接触履歴**: 面談・贈答・セミナー献金（パーティー券購入）を統合したタイムライン。「関係マスタ」へのリレーションあり。個別ページの「＋履歴を追加」から新規追加、各行の「編集」「削除」から更新・削除が可能。
- **データ品質メモ**: 元データ（CSV）の既知の不備・要確認事項。「関係マスタ」へのリレーションあり。

個別ページは「議員マスタ（全体）」712名全員が対象。関係マスタに登録がある議員は現状・パーティー券購入累計・社内担当・最終接触・接触履歴も表示され、未登録の議員はこれらがN/A表示（ドメイン/サーバー/SSL情報のみ完備）となる。

### 個別ページ上での編集（2026-07-31追加）

detail.html上の各項目（基本情報・現状・社内担当・送付先情報・備考・接触履歴）は、画面から直接編集し即座にNotionへ反映できます。
- 各フィールドグループ右上の「✎ 編集」から編集モードに入り、「保存」でNotionに反映（`updateRelation`）
- 接触履歴の各行にも「編集」「削除」ボタンがあり、内容修正（`updateContact`）やアーカイブ（`deleteContact`、Notion上は削除ではなくarchived）が可能
- 関係マスタに未登録の議員（N/A表示の議員）は、ページ上部に「＋ 関係マスタに登録」バナーが表示され、押すと氏名・政党・議院・選挙区を引き継いだ新規レコードを作成（`createRelation`、legislator_idは既存最大値+1を自動採番）。登録後はページを再読み込みして通常の編集可能な状態になる。

### CSVによる一括追加（2026-07-31追加）

「一括追加」タブ（`bulk.html`）から、関係マスタへの新規登録・項目更新と接触履歴の追加をCSV1枚でまとめて行える。

- テンプレートをダウンロード→記入例を参考にExcel等で編集→アップロードするとプレビュー（判定：新規登録／既存／エラー）が表示され、有効な行のみ「インポート実行」で反映される
- 1行＝1件の出来事。同じ議員に複数の接触履歴を追加したい場合は行を分ける
- 議員の指定は`legislator_id`優先、空欄なら氏名で関係マスタ→議員マスタ（全体）の順に完全一致検索し、未登録なら新規登録する（表記ゆれ・同姓同名は`legislator_id`指定で回避する必要がある。既知の課題は下記参照）
- 関係マスタ関連の列は**空欄セル＝変更しない**（既存値は保持される）。接触履歴の列（種別・日付・内容・備考・金額_円）は**種別が空欄の行は履歴を追加しない**
- アップロードするCSVはUTF-8・Shift-JIS（Excelの既定の保存形式）のどちらでも自動判定して読み込む
- GAS側は`bulkImport`アクション（`gas/Code.gs`）で1行ずつ処理し、1行の失敗は他の行に影響しない（行ごとに成功／エラーを返す）

### CSVによるドメイン有効期限の一括更新（2026-08-14追加）

「一括追加」タブ（`bulk.html`）下部の「CSVでドメイン有効期限を一括更新」から、議員マスタ（全体、712名）の「ドメイン有効期限」をCSV1枚でまとめて登録・更新できる。上記の関係マスタ向け一括追加とは完全に独立した機能。

- CSV列は氏名・ドメイン・有効期限（YYYY-MM-DD）の3列のみ
- 議員の指定は`ドメイン`優先（議員マスタ（全体）の「ドメイン」列と完全一致）、空欄なら氏名で完全一致検索する。表記ゆれ・同姓同名がある場合はドメイン指定を推奨（`README`の既知の課題を参照）
- GAS側は`bulkUpdateDomainExpiry`アクション（`gas/Code.gs`）で1行ずつ処理し、1行の失敗は他の行に影響しない
- 反映後は`listAll`のキャッシュが自動的に無効化される
- **この機能を使う前に、`gas/Code.gs`を変更しているため、script.google.comの既存プロジェクトを開いて「新しいバージョンをデプロイ」で反映する必要がある**（デプロイURLは変わらない。未反映の間は「不明なaction: bulkUpdateDomainExpiry」エラーになる）

### 顔写真URL（自民党、2026-08-14追加）

議員マスタ（全体）に「顔写真URL」（URL型）を追加し、自民党公式サイト（jimin.jp）の画像URLを直接参照する形で、現在の自民党所属議員分のみ収集・登録済み（他党は今のところ未収集）。detail.htmlの個別ページ上部に表示され、未登録の議員は人物アイコンのプレースホルダーが表示される。

### キャッシュによる高速化（2026-08-04追加）

`listAll`（議員マスタ712件）・`listRelations`（関係マスタ41件）・`listContactsAll`（接触履歴225件）は、ページを開くたびにNotionからフル取得すると重いため、GAS側（`CacheService.getScriptCache()`）で1時間キャッシュする方式にした。ブラウザのlocalStorageではなくGAS側でキャッシュしているため、**全ユーザー・全端末で共有される**（誰かが1時間以内に一度取得していれば、他の人が別のブラウザで開いても高速）。

- `gas/Code.gs`の`getCachedList(action, fetchFn, force)`が窓口。`listLegislatorsAll`/`listRelations`/`listContactsAll`はこれをラップしている。CacheServiceの1キー100KB制限に収めるため、JSON文字列をチャンク分割して複数キーに保存する（`cacheGetList`/`cacheSetList`/`cacheInvalidateList`）。
- 各ページ右上の「🔄 最新を取得」ボタンを押すと、`{force: true}`パラメータが送られ、キャッシュを無視してNotionから直接取得する。
- 書き込み系アクション（`updateRelation`/`createRelation`/`addContact`/`updateContact`/`deleteContact`/`bulkImport`/`bulkUpdateDomainExpiry`）が成功すると、影響するキャッシュ（例: `updateRelation`→`listRelations`）をGAS側で自動的に無効化し、次回は誰であっても必ず最新を取得する。
- フロント側（`gas-client.js`の`GasClient.fetchLists(actions, force)`）はキャッシュを持たず、単純にGASへ問い合わせるだけ（余計な往復を増やさないことで、GAS側の一時的な不調に当たる確率も下げている）。
- **`gas/Code.gs`を変更しているため、script.google.comの既存プロジェクトを開いて「新しいバージョンをデプロイ」で反映する必要がある**（デプロイURLは変わらない）。`CacheService`は追加のOAuth権限承認を必要としないため、再デプロイ時に新たな承認画面が出ることはない想定。

## 既知の制約・今後の課題

- ニュース欄はRSS連携が未整備のため空表示（N/A）です。整備後にDBへ反映される想定です。
- 議員マスタ（全体）は氏名でのみ照合しているため、同姓同名（例: 鬼木誠）や表記ゆれ（旧字体・旧姓併記）が新たに発生した場合は個別に確認が必要です。
- 「政党」の表記が2つのデータベースで揺れています（関係マスタ「自民党」／議員マスタ全体「自民」など）。個別ページの「同党の議員」フィルタは末尾の「党」を無視して比較していますが、他の箇所で政党名を突合する場合は同様の正規化が必要です。
- 「表示権限」による閲覧範囲の絞り込みは現バージョンでは未実装です（全社内公開の前提）。
